# Aevum tUSD8 Invoicing — Emilio Tecnologías

Gasless stablecoin invoicing for freelancers and small service businesses,
built for the **Aevum Builder Challenge #1** (QDay / DoraHacks) on Aevum
testnet (chain **44005**) with the **tUSD8** stablecoin.

**Tracks:** Invoice Payments (primary) + Native AI Assistants (the Python
agent that reconciles payments, issues receipts, and drafts reminders).

## The problem

Freelancers lose money to slow, manual invoicing: create an invoice in one
tool, chase payment in another, reconcile by hand, and remind clients who
forget. On-chain stablecoin payment fixes settlement speed, but raw token
transfers have no invoice semantics — no amount due, no due date, no receipt,
no reminder.

## What this project does

1. **On-chain invoices** (`InvoiceRegistry.sol`): the issuer creates an
   invoice with an exact amount due, an optional named payer, a due date,
   and a hash of the off-chain invoice document. The price lives on-chain,
   so an invoice can never be marked "paid" with a dust payment.
2. **Direct settlement, no escrow:** payment moves payer → issuer in the
   same transaction. The registry never custodies funds across transactions.
3. **Gasless payment (EIP-3009):** the client signs a
   `ReceiveWithAuthorization` message off-chain; a relayer submits it and
   pays the gas. The client needs **no tQDAY**. The signed nonce is bound to
   one specific invoice, so signatures cannot be replayed across invoices.
4. **Python agent** (`agent/`): polls chain events (chunked `eth_getLogs`,
   respecting Aevum's 1,000-block limit; HTTPS polling since Aevum has no
   WebSocket RPC), reconciles them into a local SQLite ledger, generates a
   receipt for every settled invoice, and drafts escalating payment
   reminders (friendly → firm → final) for due/overdue invoices. Drafting
   is deterministic and fully offline — no external AI API, no cost — and
   drafts wait in an outbox for human review before sending.
5. **Dashboard:** the agent renders a static HTML dashboard + JSON summary
   (settled vs. outstanding, per-invoice status) from the ledger.

## Architecture

```
Issuer ──createInvoice──▶ InvoiceRegistry (Aevum testnet, chain 44005)
Client ──approve+pay────▶        │  funds: payer ──▶ issuer (same tx)
Client ──signs EIP-3009─▶ Relayer┘
                                 │ events: InvoiceCreated / InvoicePaid / InvoiceCancelled
                                 ▼
                          Python agent (polls, chunked logs)
                                 ├─▶ SQLite ledger (reconciliation)
                                 ├─▶ Receipts (per settled invoice)
                                 ├─▶ Reminder drafts (due / overdue)
                                 └─▶ dashboard.html + summary.json
```

## Run it locally (5 minutes, no funds needed)

Requirements: Foundry (`foundryup`), Python 3.10+.

```bash
# 1. Build + test the contracts
cd contracts && forge build && forge test

# 2. Python environment (from repo root)
python3 -m venv .venv && .venv/bin/pip install -r agent/requirements.txt

# 3. Full end-to-end demo (starts anvil with the Shanghai hardfork,
#    deploys, creates 3 invoices, pays 1 standard + 1 gasless,
#    reconciles, generates receipts + an overdue reminder + dashboard)
bash demo/run_demo.sh
```

Or step by step against your own anvil:

```bash
anvil --hardfork shanghai --port 8545 &
cd contracts && forge script script/Deploy.s.sol --rpc-url local \
  --broadcast --legacy --private-key <anvil-test-key>
export RPC_URL=http://127.0.0.1:8545
export REGISTRY_ADDRESS=<deployed registry> TOKEN_ADDRESS=<deployed mock>
export ISSUER_PRIVATE_KEY=<key> PAYER_PRIVATE_KEY=<key> RELAYER_PRIVATE_KEY=<key>
.venv/bin/python agent/agent.py create --amount 25.50 --payer 0x... \
  --memo "Video editing - 5 clips" --client "Acme Media" --due-in-days 7
.venv/bin/python agent/agent.py pay-gasless --invoice 1
.venv/bin/python agent/agent.py watch && .venv/bin/python agent/agent.py receipts
.venv/bin/python agent/agent.py remind && .venv/bin/python agent/agent.py report
```

## Security notes

- Exact amount enforced on-chain (stored at creation; never caller-supplied
  at payment time).
- EIP-3009 nonce = `keccak256(registry, invoiceId)` binds each signature to
  one invoice; `receiveWithAuthorization` ensures only the registry can
  pull the funds, preventing front-running into a plain transfer.
- Checks-effects-interactions + a minimal reentrancy guard; registry holds
  no balance between transactions.
- Optional named payer restricts who can settle an invoice.
- The relayer pattern should be rate-limited in production (per-IP/payer
  caps, daily spend cap) — see the official starter-kit docs.
- Private keys are read from environment variables only; `.env` files are
  git-ignored. Never commit keys.
